ASP to React Migration Template

A practical starter framework to migrate large Classic ASP applications to a modern React + Web API stack using a PM -> Dev -> QA multi-agent workflow.

1) What this project is

This repository is a migration framework. It gives your team structure, starter code, documentation, and workflow automation to convert legacy Classic ASP modules safely and incrementally.

It is not a one-click ASP converter. You still migrate module by module, validate parity, and release in stages.

Planning docs React starter Express API starter GitHub issue templates Workflow automation

2) Target architecture

  • Frontend: React + TypeScript
  • Backend: Node.js + Express (can be adapted to ASP.NET Core)
  • Database: MSSQL with modernized schema and migration mapping
  • Process: PM -> Dev -> QA cycle per module

3) Repository map

4) Multi-agent model

Agent Primary responsibility Output
PM Agent Scope module, define acceptance criteria, risks, dependencies [PM] planning issue + linked DEV/QA tasks
Dev Agent Implement React UI + API + tests with parity notes [DEV] issue + pull request
QA Agent Validate parity versus legacy ASP and regression scenarios [QA] issue + sign-off/defect report

5) How to configure multi-agent workflow

  1. Push this repository to GitHub.
  2. Enable Issues, Pull Requests, and GitHub Actions.
  3. Enable GitHub Copilot for your org/repo.
  4. Create required labels: 
    pm-task
dev-task
qa-task
needs-triage
  5. Optional shortcut with GitHub CLI: 
    .\tools\bootstrap-labels.ps1 -Owner <org-or-user> -Repo <repo-name>
  6. Use title prefixes in issues: 
    [PM] ...
[DEV] ...
[QA] ...
  7. Workflow .github/workflows/auto-label-assign.yml auto-labels issues based on title prefix.
  8. Configure branch protection on main (or master) and require status check: 
    Dev PR Checks

6) Day-1 execution flow

  1. Fill docs/MODULE_INVENTORY.md with real ASP pages and dependencies.
  2. Create one pilot [PM] issue for Authentication module.
  3. Create linked [DEV] issue and implement endpoints + UI.
  4. Open PR using the repository PR template.
  5. Create linked [QA] issue and execute parity tests.
  6. Merge only after QA sign-off.

7) Local setup commands

Requires Node.js 20+, npm 10+, and Git.

cd frontend

npm run build
npm test

# Backend
cd ..\backend

npm test

  • Install Node.js and Git locally to run full checks/commits
